# PDF → Markdown：减少重复上下文

目标是减少反复传入全文和无关页面，不承诺固定 token 节省率。Markdown 是可检索工作副本，PDF 是原始依据；复杂公式、图表和版面仍需直接查看原页。

## 一次转换，按需读取

1. 登记 PDF 来源 ID、文件名、版本或文件散列、页数与访问范围，原件保存在 inputs/。
2. 优先使用可用的本地文字提取工具。扫描件按需 OCR；混合 PDF 按页判断，不把有少量页眉文字的扫描页误判为完整文字页。不为此任务默认上传未公开稿件到外部转换服务。
3. 输出到 work/pdf/<source-id>/document.md，另建 index.md 记录章节、物理页码和分块文件。保留原始提取结果；清理版只去除确认重复的页眉页脚、断词等噪声，不删除限制条件或负面结果。
4. 每页或每个跨页段落标记如 `<!-- source: S001; pdf_page: 12; printed_page: 8 -->`。物理页码从 1 起算；印刷页码单独记录。保留图号、表号、公式编号和参考文献标识。
5. 依据章节和任务切块，避免拆散表格、公式及限定语。索引记录每块路径、章节、页码范围、提取方式、异常。只加载相关块，必要时再扩大范围；不机械加载全部中间摘要。

## 提取质量验收

- 检查多栏阅读顺序、跨页表格、上下标、负号、小数点、希腊字母、脚注与图注。
- 关键数字、公式、表格结构、核心结论所在页面与 PDF 逐项核对。普通正文按章节和版面类型抽样，记录覆盖范围。
- 无法可靠提取时写 `[需回查 PDF 第 X 页：原因]`，并保留原页截图或定位。OCR 置信分数不足以证明数字正确。
- 图像不以文件名替代内容理解。涉及图中趋势、误差线、统计显著性时查看图页，不能只读图注。
- 新版 PDF 到来后使相关派生块和核验结果失效，记录需要重做的任务。

长期上下文只保留目标、冻结决定、索引、证据表和当前任务。token 数据可用时记录实测；不可用时只说明减少了哪些重复读取。全文翻译或全文核查任务仍需完整覆盖，不能为省 token 偷换成摘要。

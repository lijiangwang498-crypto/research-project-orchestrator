# 模型路由与环境适配

## 配置

| 阶段角色 | 用户指定的默认模型 | 可用工具接受时的模型标识 |
|---|---|---|
| 规划、最终审查 | Astra | gpt-6-astra |
| 低复杂度执行 | Luna | gpt-5.6-luna |
| 复杂写作、整合 | Sol | gpt-5.6-sol |

这是工作流推荐，不保证任一账户、客户端或 API 都提供这些模型。每次运行以当前模型列表和工具参数为准；不硬编码推理强度或费用。官方模型说明支持将 Luna 用于明确重复任务、Sol 用于复杂开放任务、Astra 用于高要求多步骤工作；本 Skill 的具体阶段分工是用户选择的策略。

## 三种运行方式

1. **有模型路由工具的 Agent**：检查工具 schema、权限和可用模型；已允许委派时向执行者提交任务契约和必要片段。明确模型参数并记录工具确认的实际值。主协调者维护共享状态，执行者不争写同一文件。
2. **支持手动选模型的 Work/聊天界面**：阶段结束保存 HANDOFF.md，说明建议选择的模型；用户切换后用交接继续。Skill 不能靠文本命令强制切换当前模型。
3. **单模型或无文件工具环境**：按同样阶段完成工作，实际模型如实记录；将四个核心 Markdown 文件作为可复制文本交付。无路由能力不等于自动拥有其他模型。必须指定模型的任务保持待切换。

不要自动启动另一个用户可见任务，也不要宣称 ZIP 上传就能让所有 ChatGPT 界面自动安装或运行 Skill。以目标环境真实支持的加载方式为准；只支持附件时，让 Agent 明确读取 SKILL.md 及对应参考文件。

## 最小交接提示

“继续项目。读取 HANDOFF.md、PROJECT_PLAN.md、PROGRESS.md 和下一项 READY 任务。遵守冻结决定，仅加载任务所需来源。建议执行模型为〔模型〕；实际模型未知时如实记录。完成验收后更新进度，遇到超出任务契约的判断时升级。”
